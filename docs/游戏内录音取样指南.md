# 游戏内录音取样指南

> 2026-10-01 写。给「想给角色换一个游戏角色音色」这件事用。

---

## 一、先纠正一个前提：**不需要训练**

声音克隆（**当前用阿里云百炼，旧平台硅基流动同理**）是**零样本（zero-shot）**：

- **要的不是"数据量"，是"一段干净样本"。** 一段 **6~8 秒**的单句录音就够建一个音色。
- 录 20~30 条的目的不是"喂给模型训练"，而是**让你自己有得挑**——挑那条没有戏剧腔、没有背景音、气口最自然的。
- 所以别去游戏里刷几百句，累且没用。

真正的（要训练的）方案是 IndexTTS-2 / GPT-SoVITS 那种本地部署，**必须 NVIDIA 显卡**。你的 RX 9070 XT 是 AMD，跑不了。

---

## 二、先说结论：录音**解决不了**电音感，那是模型本身的带宽上限

> ⚠️ **这一节改过一次，把第一版的归因推翻了。** 第一版说"接口只输出 24kHz 是主因"，
> 后来用**无损 WAV 逐段看频谱**才发现：平台标的 48kHz 只是**容器**，
> 硅基和阿里 CosyVoice 的 48k 与 24k 输出**逐段重合**，13kHz 以上都是 -90dB 空白。
> 所以真正卡住高频的**不是接口的采样率设置，而是模型的声码器本身**——
> 参考音频录到 48kHz 也没用，照样被压回去。

三条能确认的：

| 怀疑对象 | 实测结果 |
|---|---|
| 参考音频脏 | ❌ 排除。峰值 -1.6~-7.4dB、零削波、信噪比 72~165dB |
| 接口只输出 24kHz | ❌ **已推翻**。48k 是容器 48k、内容 24k；改接口参数救不回来 |
| **模型的有效带宽上限** | ✅ **真因**。CosyVoice2-0.5B 实测有效带宽 7.7kHz |
| 换成 Qwen-Audio-3.1 | ✅ **有效**。另一套模型，实测 10.8kHz，8~13k 段高约 17dB（2026-10-01 已切换上线） |

所以：

- 自己录音能提升的是**音色还原度**（挑到更贴合说话习惯的片段）和**解锁数据集里没有的角色**；
- 想要更亮的高频，**先在模型这一层解决**（换 Qwen-Audio-3.1，已做）；
  还想再进一步就得换引擎（火山豆包声音复刻 2.0 / MiniMax / 讯飞超拟人，均标称 48kHz，新用户有免费额度可先试）。
- **录音 + 换模型是两件事，别指望录音能治电音**；但录音治的是"像不像那个人"，这件事只有录音能治。

## 三、录音软件（Windows）

### 首选：Audacity（免费开源）

我要的是它的 **Windows WASAPI 环回**功能——**直接录电脑正在播放的声音，不用麦克风、不用音箱外放**。

设置步骤（**已装好：`D:\Audacity\Audacity.exe`，桌面也有快捷方式，双击即可**）：

1. **音频主机**（最左边那个下拉框）→ 选 `Windows WASAPI`
2. **录音设备**（第二个下拉框）→ 选带 **`(loopback)`** 字样、且**跟游戏实际出声的那个设备对应**的一条。

   ⚠️ **这里最容易选错，选错了录出来是全静音。** 判断方法：先看 Windows
   「设置 → 系统 → 声音 → 音量合成器」，看游戏那个进程正在输出到哪个设备，就选那个设备的 loopback。

   本机（2026-10-01 实测）的默认播放设备是 **`3 - Mi Monitor`（AMD 显卡 HDMI 音频 = 显示器自带音箱）**，
   所以选这条：

   ```
   3 - Mi Monitor (2- AMD High Definition Audio Device) (loopback)
   ```

   其他几条的含义：
   - `耳机 (MCHOSE V9 Turbo+) (loopback)` —— **如果你打游戏时其实戴耳机听**，就选这条
   - `数字音频(S/PDIF) ... (loopback)` —— 数字输出，没接线就是空的
   - `VoiceMeeter Input (VB-Audio VoiceMeeter VAIO) (loopback)` —— 走 VoiceMeeter 才有声音，**VoiceMeeter 没启动时是死路**
   - `麦克风 (MCHOSE V9 Turbo+)` —— **别选**，这是外录（录环境和音箱串音），不是内录
   - `VoiceMeeter Output (VB-Audio VoiceMeeter VAIO)` —— 同上，VoiceMeeter 没跑就没声音

   > **⚠️ 默认设备是「显示器音箱」不等于游戏声音就从那儿出。** 有些游戏（和外放习惯）会指定别的设备，
   > 保险做法是**先试录 10 秒**：游戏里放一句台词，看 Audacity 里有没有波形。是平的就换另一条 loopback 再试。
3. **录音声道**（第三个下拉框）→ `1 (单声道)`
   （游戏语音本来就是单声道内容，录立体声没意义还占地方）
4. **工程采样率**：窗口**左下角**那个数字 → 改成 `48000`
5. **先试录 10 秒**，看右边的电平表：**峰值落在 -6dB 附近最好，绝对不能碰到 0dB**。
   太响/太轻就调 Windows 的扬声器音量（环回录的就是系统输出音量，量在系统那边）。
   > **⚠️ 这一步千万别跳过（2026-10-01 实测教训）。** 第一次录的莫宁 / 嘉贝莉娜**峰值只有 -31dB**，
   > 白白浪费了 28dB 动态范围——虽然脚本能事后补增益，但**补回来的同时底噪也一起放大**。
   > 录之前花 10 秒把电平顶到 -6dB，比事后修划算得多。
6. 按 ● 开录，游戏里把台词一条条听过去，**每条之间故意停 1~2 秒**（脚本靠停顿切段）。
7. 录完：**文件 → 导出 → 导出为 WAV**，存成 `D:\录音\角色名.wav`。
   别选 MP3 —— 有损压缩，白录。

> ⚠️ **录之前先去 Windows「设置 → 系统 → 声音 → 扬声器 → 增强音频」把它关掉。** Realtek / Dolby / DTS 这些音效增强会加 EQ 和混响，录进去就洗不掉了。

### 怎么看频谱：先建分布，再看落点（2026-10-01 修正）

> ⚠️ **这一节我第一版写错了，后来用 45 条公开数据集原始音频重测才纠正过来。**
> 教训：**对照系必须选"和你的录音同类型的东西"**——要拿**数据集里的原始录音**当基准，
> 不能拿 TTS 合成输出当基准（TTS 输出天生比原始录音低频少，会得出"你的录音低频异常"的错误结论）。

45 条数据集原始音频（原神 / 绝区零 / 鸣潮解出来的原始音频）实测分布，数字是**各频段相对 1kHz 的电平**：

| 频段 | 最小值 | 25 分位 | 中位数 | 75 分位 | 最大值 |
|---|---|---|---|---|---|
| 125Hz | -37.5 | -24.5 | -16.2 | -11.1 | **+6.2** |
| 250Hz | -26.9 | +3.0 | **+8.3** | +17.3 | **+27.7** |
| 500Hz | -3.6 | +1.2 | +3.7 | +6.6 | +9.3 |
| 2kHz | -12.3 | -9.5 | -6.9 | -5.3 | +4.5 |
| 4kHz | -18.5 | -14.4 | -13.0 | -8.9 | +1.2 |

**判据：落在 [最小值-3, 最大值+3] 之外才算异常。** 注意几个反直觉的点：

- **250Hz 中位数就有 +8.3、最大 +27.7** —— 所以"250Hz 高出 10dB"**根本不是问题**，
  我第一版拿 +5dB 当红线，误判了 moning 那条（+18.9，其实完全正常）。
- **真正偏紧的是 125Hz**：45 条最大才 **+6.2**。你录的嘉贝莉娜两次都是 **+15~16**，
  这才是真异常（低频轰鸣），而且是**跨两次录音稳定复现**的，说明来自该来源本身。
- **4kHz 别低于 -19dB**，低于这个数就是高频被砍得太狠（闷）。

实测落点（2026-10-01）：

| 录音 | 125 | 250 | 500 | 2k | 4k | 判定 |
|---|---|---|---|---|---|---|
| moning | -12.9 | +18.9 | +7.5 | -9.0 | -11.3 | ✅ 全部正常 |
| jiabeilina | **+16.4** | +14.4 | +7.3 | -5.2 | -6.4 | ⚠️ 125Hz 超标 |

**遇到 125Hz 超标怎么办**：这是低频轰鸣，会顺带把信噪比拉低。它**不是后期能修好的**
（试过 85Hz 高通 + 250Hz 削 8dB，指标反而更差）。只能在录音端解决：

1. 关掉 Windows「增强音频」（含"低音增强""响度均衡"）；
2. **别用游戏耳机的虚拟 7.1 / 环绕** —— 那套 DSP 就是低频和混响的来源，切到普通立体声再录；
3. 如果换设置后还是超标，**说明这个角色的音色本来就是低频重的**（比如暗黑系/BOSS 型角色），
   那就不是缺陷，直接照着用。

（`_rec_tool.py slice <文件> fix` 可以出一版低频修正做 A/B 对照，但**不要指望它**。）

> ⚠️ **不要在 Audacity 里做降噪、压缩、EQ 任何处理**，直接导原声。让模型吃干净原始信号比喂"处理过的"更好。

> ⚠️ 录制期间**关掉其他会出声的东西**（音乐播放器、微信提示音、视频网站），loopback 是全系统的声音，一并录进去。

### 装 Audacity 时的那个坑（2026-10-01 实际踩到）

官网下载页会给多个架构的包，**必须选 `64-bit`**，选了 `arm64` 就会报
**「CreateProcess 失败；错误代码 216 …与你运行的 Windows 版本不兼容」**——那其实是架构不匹配的报错，跟 Windows 版本无关。

你这台是 **Windows 11 / AMD64(x64)**，正确的是 `audacity-win-x.x.x-64bit`。
而且**用 zip 免安装版最省事**：解压到 `D:\Audacity`，双击 `Audacity.exe` 就能跑，不需要管理员权限、不写注册表。
判断一个 exe 到底是哪个架构：看文件名不一定准，可以直接读 PE 头（本仓库 `_get_audacity.py` 里就有这段代码）。

### 备选：OBS Studio

适合你已经在用 OBS 的情况。场景里只留「**桌面音频**」，把「麦克风/辅助音频」全部**静音**，录制输出选 `mkv` 或 `wav`。录完用 `文件 → 分离音频` 或者直接拿 mkv 喂给切片脚本（PyAV 能直接读，不用先转格式）。

### 备选：虚拟声卡（VB-CABLE / VoiceMeeter）

玩法：游戏声音输出 → 虚拟声卡 → Audacity 录虚拟声卡的输入。好处是可以**自己一边听一边录**、音量独立。装驱动略麻烦，**除非上面两种都不行，否则别折腾**。

### 不推荐

- **Windows 自带「立体声混音」**：很多新驱动（含 Realtek 新版本）已经砍掉这个选项，找不到别硬找。
- **手机对着电脑录 / 麦克风外放录**：录进去的是房间混响 + 音箱频响，直接毁掉样本。要录手机游戏就用系统自带的**屏幕录制**（iOS/安卓都录内部音频，音质比外录好得多）。

## 四、游戏里怎么录

以原神 / 绝区零 / 鸣潮为例（三个都有角色语音回放功能）：

| 要做 | 为什么 |
|---|---|
| **关 BGM，关音效，只留「语音」音量** | BGM 一进去，模型会把伴奏也一起克隆进去，出来是"带背景音乐的说话声" |
| 去**角色语音档案 / 终端 → 角色资料 → 语音**里播放 | 这里是干声，没有场景回响。战斗中的台词带混响和音效 |
| 挑**语气平稳的叙述句** | 台词的"戏剧腔"会被一起克隆。语气越平，成品越像日常说话 |
| 每条之间**停 1~2 秒** | 脚本靠停顿切段 |
| **一个角色录一段文件**，不要把两个角色录在一起 | 混了就没法拆 |
| 录 **3~5 分钟** | 大约出 20~30 条候选，够挑 |

**顺带一提**：你上次圈定的 5 条（派派 / 香菱 / 芭芭拉 / 甘雨 / Cecilia）**来源都已经有了**，录音对它们的作用是"换更好的片段"。真想录，**优先录数据集里没有的角色**——比如绝区零的 Nicole、Lucy、Corin、Ellen（上次三条路径都下不到，就是不存在公开数据），这才是录音能带来的新增量。

## 五、录完怎么处理（脚本已写好）

录完得到一个大文件（比如 `D:/录音/派派.wav`），跑两条命令：

```bash
cd F:/zhixia/.workbuddy

# 第 1 步：自动切片 + 质检 + 生成试听页
F:/zhixia/venv/Scripts/python.exe _rec_tool.py slice "D:/录音/派派.wav"
```

脚本会做这些事：

1. 用 **PyAV** 解码成 24kHz 单声道无损 WAV。24kHz 的奈奎斯特频率是 12kHz，
   而当前模型（Qwen-Audio-3.1）实测有效带宽约 10.8kHz，**够用、不会被浪费**。
   ⚠️ 注意：这一步**不是**"降电音"的手段——上一轮曾这么以为，后来被频谱实测推翻了
   （各段实际听感差别来自模型，不来自参考音频的采样率）。
2. **归一化电平**到峰值 -3dB（基准取 99.9 分位而不是最大值，防一个毛刺把整段增益压下去）；
3. **自适应阈值**找停顿——底噪按你这段录音自己的第 10 百分位估，不写死数值，所以游戏内录和数据集的参数不用手动改；
4. **按「自然句」切**——VAD 分出来的每一段就当成一句话直接用，只丢碎片，另外补一版「相邻两句连读」的长参考。
   **切点绝不落在句子中间**（这是 2026-10-01 用户实测出来的关键：切出半句话做参考，克隆会明显不像）；
5. 每段导出 **24kHz / 单声道 / 16bit 无损 WAV**，前后 60ms 留白 + 15ms 淡入淡出（消咔哒声）；
6. 质检每段：峰值、信噪比、是否削波、**谱平坦度**（就是查电音感用的那个指标）；
7. 生成一个试听页，合格的段标绿。

想在切片前顺手做一版低频修正（85Hz 高通 + 250Hz -8dB）作对照，在命令后面加 `fix`：

```bash
F:/zhixia/venv/Scripts/python.exe _rec_tool.py slice "D:/录音/派派.wav" fix
```

```bash
# 第 2 步：把挑中的段（编号填试听页上的）上传成音色并合成试听
F:/zhixia/venv/Scripts/python.exe _rec_tool.py upload 派派录音 3 7 9
```

上传会自动做 ASR 拿参考文本（**必须逐字对齐**，这是克隆准不准的关键），然后建音色、按统一文本合成一条 WAV 放到 `uploaded/` 下。
文件名是中文没关系，脚本会自动转拼音（平台只接受字母、数字、`_`、`-` 组成的音色名）。

> ⚠️ **现状提醒（2026-10-01）**：`_rec_tool.py upload` 目前建的音色在**硅基流动**（旧平台/兜底线）。
> 当前线上跑的是阿里，要建阿里音色得走 `customization` 接口的 `create_voice`
> （`target_model=qwen-audio-3.1-tts-flash`，参考音频**只收公网 URL**）。这条链路还没并进这个脚本。

**选好之后不用再手动改云端配置了。** 把音色名告诉我，我加进 `voice.VOICE_CATALOG`
（约十行死数据），之后在 **App 设置页「她的声音」里就能试听、一键切换** ——
不用重启她的脑子，也不用重新打包客户端。

## 六、避坑清单

- ❌ 转成 MP3 再上传——有损压缩。脚本输出的是 WAV，别自己转。
- ❌ 在洞穴 / 大厅里录的战斗台词——混响会被克隆进去。
- ❌ 音量录制时顶到 0dB——削波是不可逆的，脚本会标红。
- ❌ 参考文本和音频对不上——脚本用 ASR 现取，不要手打。
- ❌ 拿 B 站视频 / YouTube 合集当音源——那是**二次有损压缩 + 通常带 BGM**，比游戏内录差一大截。

# 时间感与主动性修复

日期：2026-09-29
范围：云端大脑（`brain/brain.py`、`brain/server.py`）+ 手机端 UI（`_chat.html` / `assets/chat.html`）

---

## 一、你反馈的三件事

| 你的原话 | 表面现象 | 真实原因 |
|---|---|---|
| 「她没有时间观念吗」 | 上午 6~10 点反复说"约定的那个周末"，像还没到 | 上下文里的历史消息**没有时间标记**，模型分不清那是几小时前说的 |
| 「app 不能看每次聊天的时间」 | 刚聊的消息一条时间都不显示 | `/api/chat` 压根**不返回时间**；前端只在跨天时插一条日期分隔线 |
| 「聊天记录只截至到 29 号」 | 往前翻不了 | 前端硬编码 `limit=60`，只取最后 60 条 |

其中第一条还牵出一个你没提但更要紧的问题：**她凌晨 4:17 起连着给你发了 8 条消息**（到 10:58，每 40 分钟一条）。

---

## 二、根因（三处独立的实现缺陷）

### ① 主动搭话完全不读配置 —— 凌晨发消息就是这么来的

`server.py` 的 `_proactive_loop` 里写死了一行：

```python
time.sleep(2400)          # 硬编码 40 分钟
ans, _mode = b.chat(PROACTIVE_RULES, proactive=True, log=False)
```

`config.json` 里那个 `proactive` 段——`enabled`、`max_per_day`、`interval_sec`、
`quiet_start`、`quiet_end`——**一个字段都没被读**。你在配置里设的静默时段
`24:00~24:01` 本来就无效（中间只隔 1 分钟，等于没设），而且就算设对了代码也不会理。

结果：**启动后每 40 分钟一轮，24 小时不停，一天理论上能主动发 36 条**。

### ② 历史消息灌回时丢掉了时间戳

存档 `chat_history.jsonl` 里**每条都写了时间**（`_log_turn` 和
`_cloud_append_assistant` 都有写 `t`），但 `seed_history()` 灌回上下文时只取了
`role` 和 `text`，把 `t` 扔了：

```python
# 改前
self.hist.append({"role": role, "content": m.get("text", "")})
```

于是她的上下文里是一排裸的"约定的那个周末"，没有任何东西告诉模型那是几小时前说的。
模型只能默认「这是我此刻正在谈的事」，所以反复提起。

### ③ 接口不返回时刻，前端只能传空

```python
# 改前
self._json(200, {"reply": ans, "mode": mode, "err": err})
```

前端对应就是 `addMsg('assistant', d.reply, '')`——第三个参数（时间）是空串。
而且 `addMsg` 只在**跨天**时才插分隔线，同一天里聊几十条，界面上一条时间都看不到。

## 三、改了什么

### 1. 主动搭话接上配置（`server.py`）

新增 `_proactive_conf()` / `_parse_hhmm()` / `_in_quiet()` / `_proactive_used_today()` /
`_proactive_count_up()`，循环改成每轮重新读配置：

- **间隔**：读 `interval_sec`（顺手从 2400 调到 3600，一小时一次更自然）
- **静默时段**：读 `quiet_start` / `quiet_end`，**支持跨零点**（如 23:00~07:00）；
  解析不出来或起止相等就当作"没设静默"——宁可照常说话，也不猜错把她整天闷住
- **每日上限**：读 `max_per_day`，计数落在 `data/proactive_quota.json`，跨天自动归零
- 每轮读配置的好处：改完 `config.json` **不用重启大脑**就生效

配置同步改（本地 + 云端两份都改）：

| 字段 | 改前 | 改后 |
|---|---|---|
| `quiet_start` | `24:00` | `23:00` |
| `quiet_end` | `24:01` | `07:00` |
| `max_per_day` | `99` | `6` |
| `interval_sec` | `2400` | `3600` |

### 2. 历史消息带时间标签（`brain.py`）

- 新增 `Brain._stamp()`，产出形如 `[09-29 11:43] ` 的前缀
- **三处**进上下文的地方统一打标签：正常聊天（user/assistant 各一条）、主动搭话、
  场景搭话
- `seed_history()` 改用存档里的真实时间：`[09-29 06:18] 约定的那个周末`
- 新增 `HIST_TIME_NOTE`（190 字），在 system 里说明标签读法。**必须说明**，
  否则模型会犯两种错：把方括号当正文一起模仿；或者直接忽略标签、继续把老消息当现在的事
- 只有 hist 里真存在带标签的消息时才注入这段说明，不打标签就不花这份 token

### 3. 接口返回时刻 + 前端显示（`server.py` + `_chat.html` ×2）

- `/api/chat` 返回加 `t` 字段（格式与历史接口一致：`YYYY-MM-DD HH:MM`）
- 前端 `addMsg` 改成：**跨天、或距上一条超过 5 分钟**就插一条时间分隔线（像微信），
  而不是只按天插
- 自己发的消息用新增的 `nowStr()` 打时间；`renderHistory()` 同步重置 `lastT`
- 历史 `limit` 60 → 300

## 八、已知局限

1. **中文没有时态标记**，模型仍可能在极端情况下把过去的事说成将来。时间标签是
   把信息交给它，不是替它做判断。
2. **静默时段按服务器本地时间判断**（东八区），与你手机一致；如果哪天服务器换了
   时区，这个判断会跟着漂。
3. `max_per_day` 只统计**主动搭话**，你自己找她聊天不计入。
4. `_proactive_used_today()` 读不到计数文件时按 0 处理，即文件被删等于当日重新计数——
   这是刻意的（宁可多发两条，也不要因为文件损坏整天不说话）。
